## Section 7: Failure Analysis

There was no terminal campaign failure, timeout, idle kill, CI failure, CCRA finding, or merge failure. The session exports nevertheless record eight local tool commands that exited with code 1 and were corrected within the same sessions:

| Session | Recovered command failures | Observable signatures |
|---|---:|---|
| [#2](https://github.com/edburns/dd-3068633-win32-x64-03/issues/2) phase 1 | 4 | Encoded GitHub contents path returned HTTP 404; PowerShell helper argument binding produced non-JSON input; incompatible `gh pr view --comments --json` flags; another corrected probe |
| [#2](https://github.com/edburns/dd-3068633-win32-x64-03/issues/2) phase 2 | 1 | PowerShell interpolated `#$pr:` as an invalid variable reference |
| [#3](https://github.com/edburns/dd-3068633-win32-x64-03/issues/3) phase 1 | 3 | PowerShell interpolated `#$issue:` as an invalid variable reference; two corrected validation/probe commands |
| [#3](https://github.com/edburns/dd-3068633-win32-x64-03/issues/3) phase 2 | 0 | None |

### Root causes

1. **PowerShell interpolation ambiguity.** A colon immediately after `$pr` or `$issue` was parsed as part of a scoped variable expression. Delimiting variables as `${pr}` and `${issue}` corrected the commands.
2. **CLI capability mismatch.** The installed `gh` version rejects combining `--comments` and `--json`; rerunning with JSON fields alone succeeded.
3. **GitHub contents-path handling.** URL-encoding the full repository-relative path made GitHub interpret it as one filename. Passing path segments normally resolved the lookup.
4. **PowerShell array binding.** A helper accepting `[string[]]` did not preserve the intended native-command argument structure and caused non-JSON output to reach `ConvertFrom-Json`. Explicit `gh` calls removed the ambiguity.

### Impact

The errors caused extra tool calls and latency but no repository mutation, lost work, invalid success fallback, or reduced validation. All final gates were rerun successfully after correction. The clean phase-2 execution for [#3](https://github.com/edburns/dd-3068633-win32-x64-03/issues/3) shows that the campaign could complete without transient errors once the command patterns were stable, even though lesson propagation was disabled.

## Section 8: Observations and Recommendations

### 8.1 What Worked Well

- **Full task completion:** Both target issues merged and closed with a 100% completion rate.
- **Strong first-review quality:** Both CCRA reviews returned zero comments and zero unresolved threads.
- **Exact-HEAD validation:** Local tests, CI checks, review identity, effective diff, and final merge state were all tied to immutable HEAD SHAs.
- **Regression preservation:** The suite expanded from six to fourteen passing tests while retaining Fibonacci behavior.
- **Scope discipline:** Each PR changed only the production script and its test file.
- **Serial dependency enforcement:** The factorial task started only after the Fibonacci PR merged.
- **Cleanup:** Topic branches and temporary worktrees were verified absent after merge.

### 8.2 What Could Be Improved

- Eight recovered command failures are high for a two-task campaign, even though none affected the outcome.
- Stage 30 consumed 24m 36s, or 74.7% of recorded session time. Some repeated GitHub state probes could be consolidated without weakening the final atomic gate.
- Token counts were redacted, limiting cost comparisons. AIU and premium requests are available, but they are not direct substitutes for input/output token measurements.
- The logs do not emit a normalized `Comments generated` record. Review comment totals had to be derived from API output such as `commentCount` and `TOP_LEVEL_COMMENTS`.

### 8.3 Recommendations

1. **Harden PowerShell templates.** Use `${variable}` whenever punctuation follows an interpolated variable, especially `:`. Add parser-only tests for generated PowerShell command blocks.
2. **Centralize tested `gh` wrappers.** Provide helpers for content retrieval, PR JSON, GraphQL pagination, and native exit-code capture. Test them against the minimum supported `gh` version.
3. **Avoid full-path URL encoding.** Encode individual path segments only when needed; preserve `/` separators for GitHub contents endpoints.
4. **Emit normalized stage summaries.** Each phase should persist issue, PR, start/end timestamps, review rounds, comments generated, failed command count, final SHA, checks, and outcome as structured JSON. Post-mortem generation would then avoid parsing conversational exports.
5. **Record unredacted aggregate token counters when policy permits.** Store only numeric input/output totals, not prompts or responses, to improve treatment/control cost comparisons.
6. **Distinguish recovered orchestration errors from task failures.** Add explicit counters such as `toolCommandFailuresRecovered` and `terminalFailureSignature`.
7. **Retain the fail-closed final gate.** Consolidate exploratory probes, but do not weaken the atomic HEAD, review, check, base, mergeability, and issue-link verification immediately before merge.

### 8.4 Control-Campaign Interpretation

Because lesson propagation was `off`, this run establishes a clean control baseline: two small serial tasks, first-review convergence, no local remediation, 34m 11s wall time, and 194.84654 measured AIU. Comparisons with treatment campaigns should keep task scope, runner version (`1.0.4`), CLI version, repository state, and review availability constant. The sample size is too small to attribute the faster second task to any causal factor.
